/ 03

Hooks: stale closure

Классическая задача на реальное понимание React. Разбери баг и три фикса — запускай каждый вариант и смотри на консоль.
useEffect(() => {
  const handler = () => setCount(count + 1); // count захвачен с 1-го render!
  window.addEventListener("click", handler);
  return () => window.removeEventListener("click", handler);
}, []); // ← пустые deps: handler живёт вечно со старым count
Stale closure. handler захватил count=0 из первого render. deps=[] → переподписки нет → каждый клик считает 0+1.
const handler = () => setCount(prev => prev + 1);
// ↑ функциональный апдейт: closure не нужен,
// актуальное значение даёт сам React
Работает. prev всегда актуален. Лучший фикс для «инкрементов» — deps=[] остаются валидными.
useEffect(() => {
  const handler = () => setCount(count + 1);
  window.addEventListener("click", handler);
  return () => window.removeEventListener("click", handler);
}, [count]); // ← переподписка на каждое изменение count
Работает, но каждый render с новым count = removeEventListener + addEventListener. Для interval/listeners на горячих данных — churn. Иногда это ок, иногда нет.
const countRef = useRef(0);
useEffect(() => { countRef.current = count; }); // синхронизация

const handler = () => setCount(countRef.current + 1);
// ↑ ref всегда держит последнее значение, closure не устаревает
Работает. Паттерн «latest value ref»: подписка создаётся один раз, значение всегда свежее. Тот же механизм внутри многих библиотек.

на интервью сначала назови баг вслух, потом предложи все три фикса и скажи про trade-offs — это и есть senior-ответ

/ 06

React + TypeScript

Generics, discriminated unions, narrowing, utility types. Эталонный паттерн — типизированный useFetch<T>.
useFetch.ts — generic hook
type FetchResult<T> = {
  data: T | undefined;
  loading: boolean;
  error: Error | null;
};

function useFetch<T>(url: string): FetchResult<T> { /* … */ }

// discriminated union — narrowing через status
type Query<T> =
  | { status: "idle" }
  | { status: "loading" }
  | { status: "success"; data: T }
  | { status: "error"; error: Error };

unknown vs any: unknown заставляет сузить тип перед использованием — any выключает проверку entirely

Q1Данные из fetch ещё не проверены. Какой тип?
unknown — безопасный верхний тип: компилятор заставит сделать narrowing (type guard / zod) до использования. any отключает проверки.
Q2Какая запись — корректный discriminated union для состояния запроса?
Вариант 2: поле status — дискриминант. TS сам сужает тип: в ветке success data существует, error — нет. Вариант 1 допускает data+error одновременно.
Q3Типизация ref для <input>:
useRef<HTMLInputElement>(null): ref создаётся пустым и React присваивает DOM-узел при commit. Также знай React.ComponentProps и React.ElementRef для проброса props.
